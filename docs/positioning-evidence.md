## First participant study

**Question.** Does the guided lesson help a person distinguish a rejected proposal
from an accepted write whose response was lost?

**Task.** Give each participant a wrong-calculation case and a lost-response case.
Ask them to explain whether the application changed, which record supports that
answer, and whether another write is appropriate.

**Comparison.** Use the interactive lesson for one group and a static screenshot
of the source, proposal, and result for another. Assign the format before the
session; use the same instructions and examples. Record the assignment and any
help given. This is a small formative study, not a conversion-rate experiment.

**Record per task.** Format, scenario, start and end time, correct explanation,
whether help was needed, and whether the participant proposed a duplicate write.
Use participant codes and avoid recording personal information in the public result.

**Report.** Publish participant count and raw task outcomes with the materials
used. Compare completion time and explanations. State limitations and the change
made in response. Add the observed result to the resume only after it exists.

**Decision.** If participants confuse a write response with final application
state, improve that explanation and rerun the task. If the lesson is understood,
use the same method for a real product onboarding problem with its actual users.
