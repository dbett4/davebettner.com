    Evidence-grounded accounting agent · Acceptance Lab

    Let an accounting agent propose without letting it approve itself

    The problem

    A synthetic reconciliation workflow that normalizes records, retrieves policy, validates model proposals, stops unsafe cases, and recovers an uncertain write without duplicating the ledger effect.

    What I built

    I built one offline workflow that parses synthetic records, handles exact matches deterministically, retrieves policy for exceptions, validates recorded model proposals, binds approval to the exact action, and reads the synthetic ledger before retrying an uncertain effect.

    Why it matters

    Finance teams can see which evidence the agent used, why it stopped, and whether an authorized action happened exactly once.

    Proof and honest limit

    Proof32 tests; 12-case offline demo; lexical retrieval 10/16 versus hybrid and reranked retrieval 16/16; zero false or unsupported accepts in the held-out fixture; public CI and container restart proof.

    LimitSynthetic data and recorded model responses. The 16-case benchmark is a regression fixture, the verifier is local deterministic code, and no live accounting system or provider is involved.

  2. 02
    1. Write

    Failed-write recovery · Hermes Deployment Lab

    Recover a failed write without creating a duplicate

    The problem

    The system may save a payment, order, access change, or customer update just before the connection fails. This lab finds the first result before it tries the action again.

    What I built

    I built the approval and recovery path around that failure. The lab keeps one tracking number through the restart, finds the first result instead of repeating the action, and checks the final count. The public test forces the failure rather than assuming recovery would work.

    Why it matters

    A team can recover from an uncertain result without choosing between a duplicate and a manual investigation.

    Proof and honest limit

    ProofPublic GitHub Actions run 31892965924 forces the failure, restarts the containers, replays the original request, and verifies the final count is one. The suite includes 241 credential-free tests.

    LimitThis is a synthetic lab, not a live client environment. The cloud configuration is checked but not deployed. Scripts and tests drive the run; a model is not running the workflow in production.

  3. 03
    1. Confirm
    2. Write
    3. Readback

    Limited system access · Regulated Reporting MCP

    Give an agent only the write access its job requires

    The problem

    A reporting-system connector that exposes three guarded tools by default, refuses unconfirmed writes, reads results back, and keeps client values out of its receipts.

    What I built

    I built an MCP server with OAuth, retries, pagination, async polling, and a write gate enforced in code. The default server exposes three guarded tools; the full registry requires an explicit unsafe opt-in.

    Why it matters

    Teams can test useful automation without opening every write path or trusting the model’s own success message.

    Proof and honest limit

    ProofCredential-free test suite, full tool-contract coverage, and an offline end-to-end demo that runs without credentials.

    LimitA local write receipt is not treated as remote verification. Uncertain formula results are reported as indeterminate, not guessed.

How to read the public proof and its limits

These labs are independent engineering work, not customer-production agent deployments or a claim of production software-engineering tenure. Independent work is not a customer Hermes Enterprise deployment or Nous affiliation.
